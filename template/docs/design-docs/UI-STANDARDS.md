## Current Conventions

Read project-specific visual and interaction conventions in `docs/ui/README.md`. Follow the nearest live screen and shared primitives.
Do not impose one layout style on every product. Preserve useful density, clear labels, and consistent action placement.
Use semantic structure, accessible names, visible focus, and keyboard paths.
Check text and control contrast, zoom, and unobscured focus. Do not communicate status or errors through color alone.
Check long content, small screens, empty results, loading, validation errors, and denied actions for the changed surface.
Current feature-specific contracts belong in `docs/ui/INTENTS.md` only when they add information beyond code and product state.

## Evidence

A screenshot can show visual layout. It cannot prove keyboard interaction or server authorization.
Use browser or manual interaction evidence when appearance alone cannot establish the expected behavior.
